Your agent stops forgetting what it was doing.

Autocache is session continuity for AI coding agents. Hooks record the arc you are working on. The next session opens with it already loaded.

The problem

You close the terminal. You come back. It is gone.

Not the files. The files are fine. What is gone is everything around the files: which of the four approaches you settled on, the two you already ruled out and why, the test that is red on purpose, the thing you were about to do next.

So you re-explain. You paste the same three files back in. You watch the agent confidently redo work you finished yesterday, or undo a decision you made for a reason it no longer knows about. Every time.

  • The arc - a multi-day refactor reads as five unrelated first sessions.
  • The rejects - the approach you tried and abandoned gets proposed again.
  • The state - which tests are red on purpose, which migration already ran.
  • The handoff - you switch from one agent to another and start from zero.
  • The next step - the one line you would have written first if you remembered.

Context windows do not survive a session boundary, and neither does a prompt cache. Autocache does not extend either one. It writes the small amount of state that matters to disk, and reads it back at the start of the next session.

How it works

Three moving parts. All of them are files.

No MCP server, no daemon, no compiled binary, no signing chain. Node scripts your agent already has a runtime for, and JSON you can open in any editor.

01 / capture

Hooks record the arc

Lifecycle hooks watch the session as it happens. Tool calls append to the open breadcrumb. Stop writes a checkpoint. Nothing asks you to remember to save.

SessionStart      restore
UserPromptSubmit  recall a finding
PreToolUse        advise, never block
PostToolUse       append a step
Stop              checkpoint the arc
02 / persist

State is plain JSON on disk

One directory, one file per record, written atomically as .tmp then renamed. Readable, greppable, diffable, deletable. Nothing is encoded, compressed, or hidden.

~/.autocache/
  config.json
  sessions/
  breadcrumbs/
  checkpoints/
  state/
  reminders.json
  logs/events.jsonl
03 / restore

The next session opens loaded

The open breadcrumb, its completed steps, the next action, due reminders, and the last summary are injected as context before your first prompt. One state directory, many front ends.

/resume      pick the arc back up
/status      what is open right now
/checkpoint  save a restore point
/handoff     packet for another agent
/export      dump a session to disk
Free vs paid

Autocache remembers your work. Autonomous remembers your knowledge.

That line is the whole boundary. Autocache is complete for what it does: it holds one machine, one work arc, and it never forgets what it was doing. It also never gets smarter. If you want something that accumulates across projects and months, that is the paid tier, and it needs an index that hooks and JSON genuinely cannot provide.

Install

Under thirty seconds, on any of three surfaces.

The hook scripts and the ~/.autocache/ state directory are shared verbatim. A session started under Claude Code is resumable under Codex.

Installs as a plugin. Hooks, skills, and slash commands register themselves; there is no build step and nothing is compiled.

In a Claude Code session 
/plugin marketplace add autocache-ai/autocache
/plugin install autocache

Restart the session. The next SessionStart writes ~/.autocache/ and the block at the top of this page is what you see. Verify with /status.

Codex is not the plugin format. The installer materializes the same skills, hooks, and rules into the real directories under ~/.codex/.

macOS and Linux 
curl -fsSL https://autocache.ai/install.sh | sh
Windows, PowerShell 
irm https://autocache.ai/install.ps1 | iex

Writes ~/.codex/skills/autocache-*/, ~/.codex/hooks/, and ~/.codex/rules/autocache.md. Same Node scripts, same state directory as Claude Code.

Grok is a skill and prompt surface, not a hook surface. Autocache ships markdown only there. Grok reads ~/.autocache/ and narrates what is open; it does not write state and it cannot record a session on its own. Start and record arcs from Claude Code or Codex, then read them from Grok.

Fetch the skill markdown 
git clone https://github.com/autocache-ai/autocache
cd autocache/surfaces/grok

Paste the skill bodies into your Grok skill directory. Read-only by design; see docs/install-grok.md for the exact limits.

What it is not

The short list of things Autocache does not do.

It does not read your code

Hooks record session metadata: breadcrumb steps, findings you or the agent state, tool names, timestamps. No file contents are copied into state, and nothing indexes your repository.

It does not phone home

No network calls at runtime. No analytics on this page either: no CDN, no web fonts, no tracker. Telemetry exists as a flag in config.json and it is off unless you turn it on.

It is not a prompt cache

Anthropic's prompt cache is a short-lived prefix match on the API side. Autocache has nothing to do with it and does not extend it. The name refers to caching your work context on disk.

It does not make the model smarter

It restores context at the start of a session. That is the entire claim. The model is the model; it just stops starting from nothing.

It does not sync across machines

State is local in v1. If you work on two machines you have two independent state directories. Syncing them is your call and your storage.

It does not get in the way

Every hook fails open: any error, malformed input, or missing file exits zero and silently. A continuity tool that breaks the session it protects is worse than no tool. Delete ~/.autocache/ and everything still runs.

Upgrade

When the breadcrumbs pile up, you will ask whether it can learn from them.

That question is the paid tier. Autocache holds a work arc; it has no memory of anything outside it. Autonomous adds the layer that turns accumulated sessions into a knowledge base you can query.

Autonomous

Everything in Autocache, unchanged, plus an MCP server that indexes what you have already accumulated. Exactly what it adds:

  • Extraction - corrections, decisions, and discoveries become durable, typed records instead of scrollback.
  • Retrieval - semantic, lexical, and graph search over the corpus, not a grep over one directory.
  • Knowledge writes with propagation - an update lands in every dependent reference, not just the file you edited.
  • Consolidation - dedup, merge, and staleness detection so the corpus stays worth reading.
  • Context budgeting - load, warm, and offload knowledge as the window fills.
  • Learning analytics and eval - measure whether what was captured actually changed later behavior.

Autocache remembers your work. Autonomous remembers your knowledge. The free tier is not a trial and does not expire; if a work arc is all you need, stay on it.
